# 디자인/기술 문서

## 1. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 게임 엔진 | **Phaser 3** | 타일맵, 충돌 처리, 스프라이트 애니메이션, 카메라 컨트롤 등 표준 지원. 모바일 브라우저 터치 이벤트도 기본 지원 |
| 언어 | TypeScript 권장 | 씬/스테이트 관리가 많아 타입 안정성이 유리 |
| 빌드 | Vite | Phaser + TS 조합에 표준적으로 쓰이는 가벼운 번들러 |
| 배포 | 정적 호스팅 (Vercel/Netlify 등) | 별도 서버 로직 불필요 (RSVP 폼을 붙이는 경우 별도 검토) |
| 맵 툴 | Tiled | 타일맵 에디터, JSON export로 Phaser에 로드 |

## 2. 플랫폼 & 반응형 기준

- **모바일 전용**: 세로 화면(portrait) 기준으로 설계. 카카오톡 인앱 브라우저에서의 동작을
  최우선으로 확인
- 기준 해상도(캔버스 논리 해상도) 예: **720 × 1280** (9:16), Phaser의 `Scale.FIT` 모드로
  다양한 기기 화면비에 맞춰 레터박스 없이 꽉 차게 스케일링
- 데스크톱에서 열람 시에도 깨지지 않도록 최소한의 대응(중앙 정렬 + 배경 여백)만 처리,
  데스크톱 전용 최적화는 범위 밖

## 3. 조작 방식

- **탭투무브(Tap-to-move)**: 화면을 터치하면 해당 좌표까지 캐릭터가 타일 충돌을 고려한
  경로로 자동 이동
- Phaser 내 경로탐색은 간단한 맵 규모(예식장 내부 축약 맵)를 고려해 A\* 라이브러리
  (`easystarjs` 등) 또는 자체 그리드 기반 최단 경로로 구현 가능
- 이동 중 다른 지점을 탭하면 목적지를 갱신
- NPC/트리거 존에 도달하면 자동으로 대화창 또는 퀴즈 모달 오픈 (별도 확인 버튼 불필요,
  다만 오탐 방지를 위해 트리거 반경은 넉넉히 설정)

## 4. 아트 스타일

- **스타듀밸리풍 도트 아트**: 게더타운보다 디테일이 살아있는 16px 또는 32px 기반 타일/스프라이트
- 팔레트: 웨딩 컨셉에 맞춘 아이보리·블러쉬핑크·그리너리(연두/카키)·골드 포인트 톤 
  (map.md에서 정리한 실제 예식장 인테리어 톤 반영: 대리석 화이트, 골드 라인, 플라워핑크,
  그리너리)
- 캐릭터: 하객(플레이어) 1종 + 신랑/신부 NPC 2종. 각 4방향(상하좌우) walk 애니메이션 필요,
  idle 포함
- UI 폰트: **Galmuri11로 확정** (OFL-1.1, 완전 재배포 허용). 프로젝트가 실제 쓰는 글자만
  서브셋해 `game/public/fonts/`에 자체 호스팅 중 (Regular 8KB, Bold 7KB). 새 대사가 추가돼
  폰트에 없는 글자가 필요해지면 서브셋을 다시 만들어야 함 — 절차는 plan.md 8장 참고
- 실제 캐릭터/타일 일러스트는 아직 없음 — 지금은 코드로 그린 대체 그래픽(도트 블록 캐릭터,
  체커보드 바닥)으로 자리만 잡아둔 상태. 현재 상태와 남은 작업은 plan.md 8장(Phase 5) 참고

## 5. 화면/씬 구성

| 씬(Scene) | 내용 |
|---|---|
| `BootScene` | 에셋 프리로드, 로딩 화면 |
| `IntroScene` | 타이틀, 신랑신부 인사, 시작 버튼 |
| `HomeSelectScene` | 집 앞 갈림길 — 자차/지하철 선택 |
| `CarRouteScene` | 양재IC 정체 연출 + 유도선 퀴즈(Q1) |
| `SubwayRouteScene` | 노선 연출 + 출구 퀴즈(Q2) |
| `VenueLobbyScene` | 두 루트 합류, 포토테이블 NPC, 신랑측/신부측 분기(Q3) |
| `VenueHallScene` | 축의대 → 연회장 동선 안내 |
| `EndingScene` | 식사 후 귀가 연출, 신랑신부 등장, 갤러리, 마무리 CTA |

- 퀴즈 UI는 공통 컴포넌트(모달)로 구현: 질문 텍스트 + 선택지 버튼 + (오답 시) 힌트 버튼 노출
- 씬 전환 시 페이드/트랜지션 효과로 "화면 전환과 함께 퀴즈가 시작된다"는 연출 요구사항 반영

## 6. 오답/힌트 UX

- 오답 선택 시: 캐릭터가 살짝 튕겨 나오는 듯한 애니메이션 + 짧은 코믹 대사 (scenario.md
  대사 참고) → 같은 화면에서 즉시 재시도 가능
- 첫 오답 이후 "힌트 보기" 버튼 노출 → 탭하면 힌트 텍스트 표시
- 시도 횟수 제한 없음 (완주 스트레스 최소화가 목표)

## 7. 필요 에셋 목록

- [ ] 하객 플레이어 캐릭터 스프라이트시트 (4방향 walk + idle)
- [ ] 신랑/신부 NPC 스프라이트시트 (각 4방향 또는 정면 위주 최소 세트)
- [ ] 배경 타일셋: 도로/주차장(자차 루트), 지하철역(지하철 루트), 예식장 로비/복도/신부대기실/
      연회장/축의대/포토부스 (map.md 구역 기준)
- [ ] 오브젝트: 유도선(노랑/핑크/파랑), 출구 표지판, 포토테이블, 축의대 데스크, 뷔페 테이블,
      샹들리에·플라워월 등 장식 오브젝트
- [ ] UI 컴포넌트: 대화창, 퀴즈 모달, 힌트 버튼, 시작 버튼, 엔딩 갤러리 프레임
- [ ] 커플 사진 (엔딩 갤러리용) — 사용자 제공 필요
- [ ] BGM/SFX (선택) — 유쾌한 톤에 맞는 경쾌한 배경음, 정답/오답 효과음

## 8. 카카오톡 공유 대응

- Open Graph 메타 태그(og:title, og:description, og:image) 설정 → 카톡 공유 시 미리보기 노출
- og:image는 신랑신부 픽셀 캐릭터가 들어간 커버 이미지로 별도 제작 권장

## 9. 성능/호환성 고려사항

- 모바일 인앱 브라우저(카카오톡, 인스타그램 등) 호환성 확인 필수
- 에셋 용량 최소화(스프라이트시트 압축, 불필요한 고해상도 배경 지양) — 초대 링크 특성상
  로딩이 느리면 이탈 가능성 높음
- 씬 단위 지연 로딩(lazy load) 고려 (전체 에셋 초기 로딩 대신 필요 시점에 로드)

## 10. 개발 마일스톤 (초안)

요청사항이 "최대한 빨리"이므로, 아래는 우선순위 기준 초안이며 실제 착수 시 데드라인
역산이 필요합니다 (introduction.md TBD 참고).

1. **1단계 — 코어 프로토타입**: Phaser 프로젝트 세팅, 탭투무브 이동, 씬 전환 구조, 퀴즈
   모달 컴포넌트 (플레이스홀더 아트로 동작 검증)
2. **2단계 — 콘텐츠 반영**: scenario.md 대사/퀴즈 전체 반영, map.md 기준 임시 타일맵 배치
3. **3단계 — 아트 적용**: 실제 픽셀 아트 에셋 교체, 실제 예식장 참고자료 기반 맵 디테일 보강
4. **4단계 — 마무리**: 카카오 공유 대응, 모바일 실기기 QA, 로딩 최적화, 엔딩 갤러리/CTA 확정
