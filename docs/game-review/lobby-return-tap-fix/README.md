# 로비 복귀·웨딩홀 제한·연회장 터치 수정

## 반영

- 축의대·포토테이블은 동일한 (474, 360) 복귀 지점을 사용합니다. 두 안내판 사이 위쪽의 통로이며 글자와 겹치지 않고 접수/갤러리 트리거 밖입니다.
- 웰컴드링크는 (456, 970), 포토부스는 (236, 610)으로 조정했습니다. ATM은 이미 글자와 겹치지 않는 (470, 590)을 유지했습니다.
- 미완료 필수 일정이 있으면 웨딩홀 클릭 즉시 현재 위치에서 안내를 엽니다. 홀로 걷지 않습니다. 완료 후에는 정상 이동·입장이 유지됩니다.
- ‘식사를 마친다’ 버튼을 제거했습니다. 타이핑 중 터치는 문장을 완성하고, 완성 후 화면 터치는 식사를 마칩니다. 키보드로도 나레이션에 초점을 맞춰 진행할 수 있습니다. 기존 식사 순서와 진행 플래그는 유지합니다.
- 승인된 얼굴/흰 나시/의상 화살표/성별 표기/CSS는 변경하지 않았습니다. SHA-256 증거는 source-fingerprint.json에 있습니다.

## 최종 검증

최종 관련 11개 테스트 PASS (전체 저장소 전수 실행은 아님): logs/final-02.json의 7개 + logs/final-01.json에서 변경 후에도 유효한 연회장 4개(dinner-pacing 1, F20 3).

- 세 폭에서 미완료 웨딩홀 클릭 전후 플레이어 x/y 동일·moving=false. 안내를 닫은 후 다른 시설 정상 방문. 신랑/신부 양측 필수 일정 완료 뒤 정상 입장 확인.
- 연회장 세 폭에서 종료 버튼 부재, 텍스트 밖의 화면 터치로 진행, 393에서 Enter로 진행. 식사 완료 플래그, 기존 음식 사진 즉시 표시, 로비 복귀 확인.
- 실제 전체 경로 2개: 신부측 식사 먼저/신랑측 예식 먼저, 촬영·로비·연회장·엔딩·메시지 저장/건너뛰기까지 통과. 콘솔/pageerror/network failure 없음.
- npm run build 최종 exit 0. tsc 및 e2e 타입 검사 포함. 기존 500kB 초과 번들 경고 유지. 최종 CSS index-CRCmKnWz.css / JS index-CzzMZreN.js.
- shipping 에셋 검사는 독립 npm run verify:assets -- --report ../docs/game-review/lobby-return-tap-fix/assets-final-01.json으로 실행. exit 0, 등록/검사 101, 디코딩 100, 오류 0. 전체 JSON을 그대로 보존했습니다. openingAssetBytes는 에셋 합계이며 이번에 전체 첫 화면 네트워크 전송량을 재측정한 것은 아닙니다.

## 실패·재시도 보존

첫 후보 (456, 360)은 글자 겹침은 없었으나 가구 이동 제한 영역 안이어서 다시 걸을 수 없었습니다. 세 폭 걷기 검사와 신랑측 예식 먼저 경로가 이 문제를 검출했습니다. 지점을 (474, 360)으로 옮기고 같은 검사를 통과했습니다. 실패를 무시하거나 검사 기준을 완화하지 않았습니다.

- journeys-01: 1 PASS / 1 FAIL. 동일 좌표 때문에 신랑측 홀 이동 실패.
- final-02: 7 PASS / 0 FAIL / 0 SKIP.
- 첫 타입 검사는 테스트 관측용 Container 타입 변환 오류로 exit 2. 실제 Player 메서드를 포함한 타입으로 명시 후 빌드 통과.
- final-01 320 실패의 trace 저장 과정에서 stream byte 수/ZIP 종료 레코드 오류가 추가 발생했습니다. 이 기록도 JSON에 남아 있으며 완전한 320 trace라고 주장하지 않습니다. 393/430 및 신랑 경로의 정상 실패 trace·영상·error-context를 보존했습니다.
