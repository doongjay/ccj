# 대화 위치·지하철·웨딩홀 GO·유도선 수정

## 최종 반영

- 모든 `StoryDialog.show()` 선택지를 처음부터 실제 크기로 배치합니다. 문구 출력 중에는 visibility/inert/aria-hidden/disabled로 보이지 않고 입력되지 않으며, 공개할 때 위치는 변하지 않습니다. 기존 240ms 중복 입력 방지도 유지합니다.
- 지하철의 말풍선+선택지 전체를 해당 말풍선의 실제 높이만큼 위로 이동합니다. 화면 크기가 바뀌면 다시 측정하며, 대화를 닫을 때 관찰자를 해제합니다.
- 포토테이블 첫 사진 문구: `현서와 재준, 현재의 시작`.
- 웨딩홀 미완료 일정마다 오른쪽에 44px 이상 `GO!` 버튼을 둡니다. 수첩 보기/돌아가기 버튼은 제거했습니다. GO는 해당 시설을 바로 열고, 복귀 위치와 진행 플래그는 기존 동작을 사용합니다. 바깥 터치 또는 Escape로 안내를 닫을 수 있습니다. 미완료 상태에서 홀 클릭만으로 플레이어가 이동하지 않습니다.
- 자동차 원래 대사: `양재IC랑 가깝군. 그런데 진입구에\n유도선이 많은데?`. LACITTA 간판 바로 아래에 대사를 배치하고 그 아래에 노란색/분홍색/파란색 선택지를 둡니다. 선택지의 목적지 설명을 추가했던 중간안은 최종본에 없습니다.
- `references/car-original-reference.jpeg`의 황토빛 노랑/분홍/차분한 파랑을 참고해 선 색상을 수정했습니다. 하단 순서는 왼쪽 노랑/가운데 분홍/오른쪽 파랑입니다. 분홍선 끝의 타워 하단은 차량이 진입할 수 있게 개방했습니다. 파란선은 오른쪽 진입부 안까지 하나로 이어지며 이전 얇은 파란선은 제거했습니다.
- 분홍/파랑 차량 경로를 각각 열린 타워/오른쪽 진입부 안까지 맞췄습니다. 노랑=이마트 지원 불가, 분홍=타워, 파랑=B3의 목적지와 진행 로직은 유지합니다.
- 승인된 얼굴·미니미·의상 선택기 코드는 변경하지 않았습니다. `source-fingerprint.json`의 SHA-256 대조 기록을 확인할 수 있습니다. F24/F25는 진행하지 않았습니다.

## 최종 화면과 영상

`after/`에 폭 320/393/430별 `subway-typing`, `subway-choices`, `hall-go`, `photo-table-caption`, `car-typing`, `car-choice`, `car-destination`, `car-lines-renderer` PNG와 `car-drive` WebM이 있습니다. renderer 이미지는 DOM을 숨긴 합성 화면이 아니라 Phaser의 실제 렌더러 출력이며, DOM 선택지는 일반 car-choice 캡처에서 확인합니다. 영상은 원본 속도 그대로이며 재인코딩·배속·실패 구간 삭제를 하지 않았습니다.

실제 화면에서 지하철 출력 전후, GO 목록, 포토테이블 캡션, 세 폭의 유도선·진입구를 열어 시각 확인했습니다. 실제 휴대전화 하드웨어 검수가 아닌 Chromium 브라우저 검증입니다.

## 실패·중간안 보존

- `before`: 원래 하단/지하철/중앙 배치의 이동을 재현했습니다. 지하철은 76~86 CSS px 이동했습니다. 테스트용 Intro 장면의 배경 시작 버튼이 가상 대화 검사를 방해한 실패도 포함되어 있습니다.
- `after-01`: 실제 장면 3개 테스트는 통과했지만 가상 배치 테스트의 Intro 시작 버튼 간섭이 남았습니다. 테스트용 fixture의 무관한 배경 입력만 비활성화하여 같은 위치/접근성/활성화 검사를 `after-02`에서 6개 모두 통과했습니다. 실제 게임 입력 로직을 바꿔 해결한 것이 아닙니다.
- 파란 접합부만 고친 중간안은 사용자 요구 전체를 충족하지 않았습니다. 원본 참고 이미지를 확인한 뒤 대사·색상·타워 개방·간판 아래 위치를 반영했고 최종 증빙은 `final-03`입니다.
- `final-02`: 320 폭의 선택지 하단이 보호 경계보다 약 1.13px 내려와 1개 실패했습니다. 문구와 선택지 간격을 16→12px로 조정하고 기준을 그대로 유지하여 `final-03` 12개 통과했습니다.
- 실패 reporter, 화면, 영상과 중간 이미지 원본은 모두 보존했습니다. 검수 ZIP에서 중복 통과 산출물을 제외했다면 `EXCLUDED_FILES.json`에 경로·크기·사유를 기록합니다.
