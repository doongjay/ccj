# 게임 시작 후 준비창 반복 표시 제거

## 변경

- `game/src/systems/stageAssets.ts`: 초기 boot 이후 정상 로딩에 사용하던 300ms 표시 타이머를 제거했다. 다음 장면의 에셋이 준비될 때까지 현재 장면을 유지한다. CSS로 로딩창을 감춘 것이 아니라, 정상 후속 로딩에서는 표시 자체를 요청하지 않는다. 캐시·진행 중 요청 공유·필수 에셋 완료 대기는 유지한다.
- 초기 진입의 큰 준비창은 유지한다. 실제 요청 실패 시에만 작은 재시도 UI를 표시하며, 키보드로 다시 불러올 수 있다.
- `game/src/ui/GameAccess.ts`: 게임 시작/이어하기 후 각 장면에서 청첩장에 필요한 양쪽 미니미 에셋을 미리 불러온다. 기존 중복 요청 방지와 텍스처 캐시를 재사용한다. 첫 진입 다운로드에는 추가하지 않는다.
- 사진 준비 로직, 사진 화질, 방명록 구현, 게임 얼굴, 장면 구성은 변경하지 않는다. 청첩장으로 바로 진입할 때 아직 없는 사진의 초기 준비·실패 재시도는 유지한다.

## 검증

`game/`에서 실행:

1. `npm run build`: 종료 코드 0. TypeScript/E2E 타입 검사와 배포 빌드 통과. 기존 500KB 번들 경고 유지.
2. `npm run test:e2e -- --config=../docs/game-review/post-boot-loading/playwright.config.ts`: **8 PASS** (`local-01.json`).
   - 실제 Chromium에서 setup 배경과 자동차를 일부러 지연시켰다. 300ms 이상 기다려도 준비창이 없고, 현재 장면이 유지되며, 응답 후 정상적으로 로비까지 진입한다.
   - 게임 중 사진 26개와 양쪽 미니미 에셋이 미리 준비된 것을 확인했다. 청첩장 열기 → 게임 복귀 → 다시 열기 동안 준비창이 없고, 관찰된 로딩 UI는 초기 boot 1회뿐이었다.
   - 직접 청첩장 진입 320×568 / 393×852 / 430×932, 사진 모아서 표시, 갤러리 열기, 사진 실패 후 키보드 재시도, 원본 보존, 로비 수첩·진행 상태 복귀를 확인했다.
3. `npm run test:e2e -- --config=../docs/game-review/post-boot-loading/production.config.ts`: **3 PASS** (`production-01.json`).
   - 자차·지하철 경로의 배포 빌드 첫 화면 전송량 각각 5MB 이하. CDP 측정은 `regressions/performance-car.json`, `regressions/performance-subway.json`에 보존했다.
   - 초기 준비창 유지, 자동차 에셋 요청의 의도적 1회 실패, Enter 재시도, 로비 진입까지 확인했다. 예상한 네트워크 실패 외 콘솔 오류 없음.

`after/`의 지연된 setup/route 화면과 게임 후 청첩장 화면을 직접 열어 준비창이 덮이지 않는 결과를 확인했다. 원본 PNG와 실제 속도 영상은 `runs/`에 보존한다. 방명록 저장 검증은 실행하지 않았다. 에셋 파일이나 검사 기준을 바꾸지 않아 에셋 검사는 재실행하지 않았다.
