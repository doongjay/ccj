# 렌더링 시각 확인

## 전수 범위

- 남성: 얼굴3 × 헤어3 × 의상6 = **54 정면 조합**, 실제 출력 시트를 모두 확인.
- 여성: 얼굴3 × 헤어3 × 의상6 = **54 정면 조합**, 실제 출력 시트를 모두 확인.
- 행은 의상1–6, 열은 얼굴1/헤어1–3 → 얼굴2/헤어1–3 → 얼굴3/헤어1–3 순서다. `after/inspection/index.json`에 108개 ID가 있다.
- `*-all-54-front-native.png`의 전체 외형과 `*-all-54-neck-4x.png`의 접합부를 따로 확인했다. 공통 목 중간의 횡단 띠가 사라지고, 턱 아래 피부가 옷의 열린 부분까지 이어지며 양쪽 목 외곽이 남아 있다. 실제 셔츠 카라·니트 재봉선·원피스 목둘레 테두리는 보존되어 있다.
- `after/inspection/motion-*-neck-4x.png` **13장 × 19프레임**을 확인했다. 각 장은 down/left/right/up/posing/seated/3blink/8walk/2clap이다. 목 내부에 남던 의상 원본 절단선과 녹색 배경 가장자리 잔여물을 정리한 최종 렌더링이다.

108개를 계산만 한 결과와 108개를 렌더링·시각 검수한 결과를 혼동하지 않는다. 실제 플레이는 아래 7조합이며, 108개 전체를 각각 완주했다는 뜻은 아니다.

## 실제 플레이 범위

| ID | 조합(표시 번호) | 확인 |
|---|---|---|
| 01 | 남성 얼굴3 / 헤어3 / 의상1 | 미리보기, A→B→A, blink, 걷기, 포토부스/신부 사진, 이어하기, 박수, 단체사진 |
| 02 | 남성 얼굴3 / 헤어1 / 의상1 | 같은 흐름, 지하철, 환호 |
| 03 | 남성 얼굴2 / 헤어1 / 의상3 | 같은 흐름, 둥근 안경, 아이보리 옷깃, 박수 |
| 04 | 여성 얼굴1 / 헤어1 / 의상1 | 같은 흐름, 흰 셔츠, 박수 |
| 05 | 여성 얼굴2 / 헤어2 / 의상5 | 같은 흐름, 회색 재킷, 박수 |
| 06 | 여성 얼굴2 / 헤어3 / 의상6 | 같은 흐름, 새 네이비 원피스, 박수 |

각 조합은 포토부스와 신부 사진 결과를 **5.5초 이상** 유지하고 명시적 복귀 버튼으로 나왔다. `observations.json`의 실제 이벤트 시각과 원본 영상으로 확인할 수 있다. 화면 캡처, 실제 Player가 사용한 texture/frame 출력, 사진 원본 PNG를 모두 제공한다. 영상에서 뽑은 시간 표기 정지화면은 `after/video-inspection/`이며 원본 영상을 대신하는 편집본이 아니다.

## 원인과 수정 방식

| 원인 분류 | 확인 내용 | 변경 |
|---|---|---|
| 공통 코드 파츠 | `neckPart()`가 `#dea073`로 목 전체 폭 12×2px를 그림 | 횡단 띠 제거, 양쪽 외곽/1px 측면 음영을 대칭으로 연결 |
| 원본 파츠 + 레이어 | 의상 원본 피부가 공유 목 위에 다시 올라옴 | 피부만 같은 색으로 정리하고 옷감/옷깃 픽셀 보존 |
| 마스크 범위 | 밝고 채도 높은 주황 피부가 기존 skin 범위 밖에 있음 | 목 내부에서 해당 피부 가장자리만 포함하도록 보정 |
| 원본 절단 경계 | headless 추가 의상의 잘린 피부 경계가 횡선으로 남음 | 공유 목 안쪽의 실제 피부 개구부만 비워 아래 목을 노출 |
| chroma 잔여물 | 새 의상과 기존 핑크 원피스 뒷목에 녹색/올리브 잔여물 | 목 내부의 좁은 경계에서만 제거 |
| 신규 의상 오프셋 | 6번 raised-hand 포즈에서 손 끝이 목 중심 계산에 섞임 | 새 원본의 카라 중심 앵커를 명시; 기존 얼굴 위치와 원래 의상 좌표는 유지 |

## UI 확인

- 320×568 / 393×852 / 430×932: 첫 수첩 터치, 촬영 버튼이 카메라 프레임 아래에 있는지, 성별 78px 높이, 의상 페이지 1–3/4–6, 남성 하늘색/여성 분홍을 확인했다.
- 자동차: 같은 세 폭의 실제 화면과 renderer PNG를 확인했다. 노랑·분홍이 분리되고 파랑은 오른쪽 진입부로 연결된다. 세 경로 실제 주행 영상과 경로 좌표 JSON을 함께 제공한다.
- 뷔페: 한 화면의 음식6장과 터치 완료/진행, 화살표 제거를 실제 자동차·지하철 여정에서 확인했다.
- 화면 전체보기/계속 터치 안내문은 보이지 않는다. 키보드 포커스와 실제 계속 조작은 유지한다.

이 문서는 렌더링 시각 확인 기록이다. 자동 회귀 검사의 최종 집계는 `TEST_RESULTS.json`으로 별도 확인한다. 기존 idle과의 픽셀 일치 검사는 보존 여부 확인용이며 얼굴·목 품질의 합격 근거로 사용하지 않았다.
