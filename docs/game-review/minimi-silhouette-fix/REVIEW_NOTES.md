# 검증 범위와 원인

## 실제 원인

이 작업 시작점에는 앞선 공통 `#dea073` 갈색 가로띠 삭제가 이미 반영되어 있었다. 그 결과만으로 목이 정상이라고 판단하지 않았다. 시작점의 `minimiParts.ts/neckPart()`는 여전히 12×19 직사각형 피부와 길이10인 1px 수직선, 별도 1px 하이라이트를 만들었다. 머리 원본의 턱 접점과 의상 시작점 사이에 긴 좁은 부분이 남아 목이 독립된 기둥처럼 보였다.

수정은 `MINIMI_NECK`의 목 시작, 짧은 수직 구간 뒤 넓어지는 실루엣, 머리의 y+3 등록으로 이루어진다. 몸과 발 앵커는 이동하지 않는다. 헤어 bounding box 중앙에 맞추지 않고 기존 턱·목 x=64를 유지했다. 옆 윤곽은 `#352c24` 2px로 통일하고 목 전체를 가르는 별도 가로 음영을 만들지 않는다.

여성 원본 머리에는 피부색 검사로 지워지지 않는 이전 목의 어두운 선이 중앙 밖까지 남았다. `classicHead()`의 정면 중앙 x52..75, y80 이후만 정리해 옆 머리카락을 보존한다. 남성은 기존 y80 이후 절단을 유지한다. 표정/안경 함수와 눈 간격은 이번 변경에서 수정하지 않았다.

추가 의상의 headless 원본은 목 절단면에 주황·빨강·노랑/녹색 matte 조각을 포함했다. 최적화 자체의 추가 열화는 아니며 새 여성6 PNG와 lossless WebP의 decoded RGBA는 같다. `extraClothingPart()`에서 등록된 목 구멍 내부와 절단 높이만 정리한다. 옆모습은 실제 비스듬한 카라 위의 처음2행 절단면을 정렬한다. 카라 아래/단추/봉제선의 작은 픽셀을 일괄 삭제하는 필터를 추가하지 않았다.

중간 01~07 시트는 목의 길이·여성 원본 윤곽·의상 절단면·옆/뒤의 잔여물을 확인하며 반복한 기록이다. 마지막 정면 108개와 13대표 동작 시트의 시각 확인은 자동 PASS와 별도로 수행했다.

## 테스트 변경과 실패 기록

1. `capture-final-01`: 실제 화면 녹화 도중 옆모습 잔여물의 추가 수정이 필요해 작업자가 중단했다. 1 PASS / 1 interrupted / 6 not run. 중단된 영상·trace·JSON을 보존하며 최종 외형 증빙으로 사용하지 않는다. `capture-final-02`가 최종 렌더 버전의 새 기록이다.
2. `dev-regression-01`의 `minimi-jaw.spec.ts`는 기존 고정 y74..79를 검사해, 머리를 3px 낮춰 앉힌 이후 y74..76에 놓인 입을 턱 seam으로 보고 실패했다. 오류의 색/좌표와 레이어 PNG를 대조했다. 동일한 10×6 검사 영역을 등록된 턱 좌표 y77..82로 옮겼으며 색 임계값·검사 면적·얼굴 썸네일 검사·outline 요구는 유지했다. 깨진 이미지 baseline은 만들지 않았다. `jaw-rerun-01`은 같은 앱 코드에 이 좌표 등록만 반영한 재검사다. 기존 D 애니메이션 보존 검사는 변경하지 않았다.
3. 같은 개발 회귀 실행은 이미 로드된 테스트 모듈이 예전 고정 증빙 경로를 사용해 19개 기존 UX 자료를 갱신했다. 실행을 중단하고 새 자료를 `recovered-ux-run01/`에 보존한 후, 변경하지 않은 원래 ZIP의 정확한 bytes로 원본을 복구했다. `old-evidence-restoration.json`에 각 경로와 해시가 있다. 새 프로세스의 재검사는 `REVIEW_EVIDENCE`를 적용해 새 폴더에만 저장한다. 중단 당시 30 PASS / 1 FAIL / 2 interrupted / 1 not run을 그대로 보존한다.
4. 로비/저장 안내의 “확인”을 찾던 테스트는 사용자가 요청한 실제 화면 터치나 키보드 진행으로 변경했다. 지하철은 사용자가 요청한 이전 문구·선택지·오답 복귀를 검사한다. 회귀 검사의 의도와 접근성 검사는 유지했다.

최종 수치와 각 실행의 종료 결과는 `TEST_RESULTS.json`에 자동 집계한다. 중간 실패를 최종 PASS 개수로 덮거나 SKIP으로 바꾸지 않는다. `verify:assets`는 작업 디렉터리를 별도 지정하고 단독 실행했다. 셸 리디렉션이나 변경되는 보고서 경로를 권한 접두사에 붙이지 않았으며, 반환 출력은 별도 로그에 보존했다.

## 범위의 한계

실제 Chromium 브라우저에서 검사했다. 모바일 세 크기는 desktop Chromium의 viewport/touch 에뮬레이션이며 iOS Safari/Android 실기기 검증은 아니다. 사용자 원본 캡처의 viewport/DPR은 알려져 있지 않으므로 추정값을 사실로 기록하지 않는다. 새 동일 조건 BEFORE/AFTER는 393×852 / DPR1이고 선택 화면 확대는 native canvas의 정수4배다. 최초3조합 선택 화면은 4개 viewport에서 비교했다.

108정면 전수 렌더/시각 검수, 13대표 동작 시트, 7대표 전체 플레이는 서로 다른 범위다. 모든108조합의 모든 방향·모든 장면을 직접 플레이했다고 주장하지 않는다. 사진·반응의 실제 프레임 시간은 운영체제 스케줄링에 따라 조금 다르므로 고정된 장면/행동 지점과 조건을 맞췄으며 움직임을 정지시키거나 재생 속도를 바꾸지 않았다.

기존 A/A1/B/C/D의 배경/로딩 전략/차량 경로/뷔페/사진 프레임/진행도/저장 구조는 보존한다. 이번 새 이미지의 성별6 의상 ID는 기존과 같으므로 이전 저장 선택도 동일한 ID로 복구된다. 첫 로딩에서 의상 전체를 미리 합성하거나 다운로드하지 않는다.
