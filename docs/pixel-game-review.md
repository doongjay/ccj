# 픽셀 청첩장 검토 기록

## 유지하는 기준

- 기존 Phaser 씬, 픽셀 배경·캐릭터·Galmuri 폰트·대화창을 유지합니다. 공간 사진은 위치와 구조 참고용이며 게임을 실사 배경으로 바꾸지 않습니다.
- 청첩장의 예식 정보와 실제 커플 사진은 [원본 청첩장](https://www.heumcard.com/cards/now-2026-11-21)을 따릅니다. 게임의 하객 캐릭터는 새로 만든 픽셀 에셋과 코드 조합입니다.
- [픽셀 청첩장 블로그](https://m.blog.naver.com/j_serendipity/223735546239)의 이미지 16개와 약 25초 미니미 선택 영상을 검토했습니다. 큰 완성형 미니미 옆 헤어/의상 선택, 계단식 단체사진, 친구 누적, 캐릭터별 메시지 열기, 페이지 넘기기를 참고했습니다. 레퍼런스 캐릭터나 워터마크 이미지는 앱 에셋으로 복사하지 않았습니다.
- [픽셀 게임 쇼츠](https://www.youtube.com/shorts/bABZGWA46DQ)의 썸네일과 전체 구간 스토리보드를 검토했습니다. 직접 영상 스트림은 내려받지 못했습니다. 또렷한 픽셀, 가벼운 눈 깜빡임과 짧은 이동 연출을 참고했습니다.

## 반복 지적 사항과 대응

| 지적 | 적용 |
| --- | --- |
| 머리·옷 이음새와 비투명 배경 | 원본 머리 영역 마스킹, 목 중심 정렬, 피부 연결, 배경 알파 정리, 정수 좌표·nearest 렌더링 |
| 얼굴과 의상을 따로 선택 | 큰 합성 미리보기 + 헤어 세 개/의상 세 개 이미지 카드, 성별 버튼 두 개, 의상 텍스트 생략 |
| 신부와 떨어져 앉음 | 소파 위 최종 위치를 신부 바로 옆으로 당김, 사진 메뉴 후 이동·앉기·플래시·자동 복귀 |
| 원판에서 겹치고 떠 있는 인물 | 30개 외형 조합, 정장·단정한 의상·안경 변형, 계단 네 줄, 발 위치와 그림자 정렬 |
| 원판을 볼 시간이 부족 | 사진 찍기 버튼, 3초 카운트다운, 촬영 후 직접 다음으로 진행 |
| 원판 UI와 멘트 | 초점/REC/타임코드 프레임, 배터리 없음, `찰칵! 결혼 축하해!` |
| 길을 무시한 이동 | 로비 장애물 우회 경로, 집·유도선·셔틀·잔디 통로·연회장 복도 경유점 |
| 연회장 길목의 불필요한 대기 | 전환 멘트 완료 뒤 추가 홀드 없이 바닥 경로로 이동 |
| 식사 후 로비로 되돌아감 | 현재 연회장/예식장 배경에서 귀가 멘트 후 엔딩 |
| 음식과 술을 처음부터 설명 | 연회장 도착 전 주류 언급 없음, 교통수단별 식사 멘트 분기 |
| 의식보다 밥을 먼저 먹는 분기 | 연회장을 먼저 눌렀을 때만 질문, 선식사 후 본식이면 두 번째 식사 생략 |
| 청첩장에 픽셀 감성이 부족 | 크림/세이지 배경, 픽셀 사진 창·하트·달력, 큰 미니미 빌더, 계단식 방명록 |

## 기술적 점검

- 목 아래 외곽선이 옷 위에 겹쳐 검은 분리선처럼 보이던 합성을 수정했습니다. 목 정렬 후 실제 옷깃을 앞에 겹치되 긴 머리·포니테일 뒷모습은 보호합니다. 남녀 18개 조합 × 9개 자세/눈 깜빡임 프레임의 연결 상태와 목 확대 화면을 확인합니다.
- 출구 간판 1~5와 이동 목적지를 같은 좌표로 관리하고, 하단 선택지와 간판이 겹치지 않는지 320px·393px 화면에서 검사합니다.
- 웨딩홀에서 유도한 활동은 일회성 복귀 위치를 씬 사이에 전달합니다. 포토테이블은 모달을 닫을 때 같은 위치로 돌아옵니다. 캐릭터 터치 영역의 원점도 보정해 문 앞 캐릭터가 웨딩홀 버튼 터치를 가로채지 않도록 했습니다.
- 숨긴 이야기 창의 DOM을 비워 이전 선택지가 중복 클릭되거나 접근성 트리에 남지 않도록 했습니다.
- 화면 전환 중 중복 입력을 막고, 시설/버튼 탭이 바닥 이동 이벤트로 전파되지 않도록 했습니다.
- 미니미 대기 중 눈 깜빡임, 터치 시 작은 하트, 로비 활동 수첩을 추가했습니다. 방문 조건을 늘리거나 게임 진행을 늦추지 않습니다.
- 미니미 선택기의 타이머는 화면 종료 시 해제합니다. 원판과 청첩장 단체사진의 깊이는 해당 화면 내부에서 관리합니다.
- 휴대폰 키보드에 맞춰 입력창 위치를 보정하고 320px 폭에서도 카드와 시작 버튼이 화면 안에 들어가도록 조정했습니다.
- 실제 청첩장 사진은 픽셀 처리하지 않습니다. 사진 확대는 키보드/스와이프/닫기를 지원하며, 사용자 메시지는 HTML이 아닌 텍스트로 표시합니다.
- 테스트용 캐릭터/메시지는 격리된 Playwright 브라우저에만 넣습니다. 실제 로컬 방명록에 가짜 하객을 저장하지 않습니다.

## 확인 방법과 한계

- `npm run build`, `npm run test:e2e -- --workers=2`로 타입·빌드·게임 경로·방명록·알파를 검증합니다.
- `e2e/minimi-visual.spec.ts`는 남녀 18개 스타일의 여섯 자세 및 세 가지 눈 깜빡임을 캡처합니다. `current-journey.spec.ts`는 부모님·신부 옆 앉기·브이·원판을 캡처합니다.
- 393×852/DPR 3, 320×568, 390/430/720px 및 데스크톱은 브라우저 에뮬레이션입니다. 물리 iPhone의 Safari·카카오 인앱 브라우저 검증을 대체하지 않습니다.
- 메시지/미니미는 현재 브라우저 localStorage 전용입니다. 실제 초대객 공유를 위해서는 서버·DB와 개인정보 처리 정책이 필요합니다.
- 공개 배포용 절대 OG URL과 카카오 공유 미리보기는 배포 주소가 정해진 뒤 확인해야 합니다.
