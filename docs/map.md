# 맵 문서 — 라시따시어터(LACITTA) 기반 예식장 맵

실제 예식장(라시따시어터, 서울 서초구 매헌로 16, 1층 그랜드볼룸) 평면도와 현장 사진을 참고해
게임 내 "예식장 로비 이후" 구역을 제작하기 위한 기준 문서. 자차/지하철 루트(양재IC, 양재역)
구간은 실제 지리를 단순화한 연출 배경으로 별도 제작하며, 이 문서는 **예식장 내부 맵**에
집중한다.

## 현재 게임 공간 구성 (2026-09-08)

로비에서 포토부스, 연회장, 대기실, 신부대기실로 각각 이동하고 다시 로비로 돌아온다.
네 공간은 예식홀 내부 장식이 아니라 별도 장면이다. 신부 NPC는 신부대기실에만 배치한다.
로비의 축의대에 도착하면 하객 구분을 확인한다. 선택한 쪽의 축의대이면 바로 접수하며, 반대편이면 해당 축의대로 안내한다. 방을 다녀와도 선택과 접수 완료 상태를 유지한다.
포토테이블에 도착하면 별도의 사진 갤러리가 열린다. 이전/다음 사진과 닫기, 방향키와 Escape를 지원하며, 닫은 뒤 구역을 벗어났다가 다시 방문할 수 있다. 갤러리는 접수 상태를 변경하지 않는다. 사진 목록은 `game/src/data/photoGallery.ts`에서 관리하며 현재는 실제 웨딩 사진 미제공으로 샘플 일러스트 두 장을 사용한다.
예식홀은 접수 후 입장하고 로비로 돌아올 수 있다. 기존 예식 안내와 엔딩 진행은 유지한다.
아래 평면도 해석과 초기 C2 동선 제안보다 이 구성이 현재 구현 기준으로 우선한다.

사용자가 설명한 로비 배치: 좌측 상단 축의대, 우측 상단 포토테이블,
중앙 에스컬레이터를 통한 연회장 이동, 우측 웰컴 드링크,
좌측 하단 대기실, 우측 하단 신부대기실 이동 경로.
별도 포토부스 입구는 하단 중앙에 유지한다. 게임 좌표는 이 상대 배치를 단순화한 것이며 실측 도면이 아니다.

신부대기실은 로비에서 바로 진입하지 않고 그리너리 통로를 거쳐 이동한다.
통로 왼쪽은 그리너리, 오른쪽은 통창이며 중간에는 포토존 마크만 배치한다.
촬영 장비나 별도 포토부스 기능은 통로에 추가하지 않는다. 통로 끝까지 걸어가면 신부대기실로 입장하고,
신부대기실에서 나오면 통로의 신부대기실 쪽 출입구로 돌아온다.

## 3. 추천 동선 (평면도 빨간 점선 기준)

평면도 원본 확인 결과, 점선 동선은 다음과 같이 이어진다:

```
우측 상단 "입구" → (우측 벽을 따라 하강) → "신부입장" 구간 → "식장" 진입(화살표)
  → 중앙 하단 "입구" → 아래로 하강 → "포토부스"
```

건물 로비(좌상단)에서 이 우측 상단 "입구"까지 도달하는 구간은 평면도에 명시적으로
표시되어 있지 않으므로, 게임에서는 "로비 입구 → 복도 → 우측 입구 → 신부입장/식장 앞
→ 포토테이블·축의대 구역 → 포토부스"로 단순화해 이어 붙인다. 이 동선을 게임 시나리오
C1~C2 스테이지의 캐릭터 이동 경로 기준으로 사용한다 ([scenario.md](./scenario.md) 4장 참고).

> 참고: 이 점선이 하객의 실제 동선인지, 신부 입장 동선(예식 진행용)인지는 평면도만으로는
> 100% 단정하기 어렵다. C1(포토테이블→축의대)과 C2(축의대→연회장) 사이 실제 하객 동선은
> 아래 5장의 화살표 안내 방식으로 단순화해 구현하고, 세부 방향은 필요 시 사용자 확인.

## 4. 비주얼 매핑 메모

- **로비 입구**: 통유리창 + 천장 그리너리 행잉 장식이 특징적 → 타일셋에 그리너리 행잉 오브젝트,
  통유리 배경, 야외 조경(오브제) 반영
- **안내데스크**: 대리석 바닥/벽 톤, 골드 라인 포인트 → 축의대 타일에 유사한 골드+화이트 톤 적용
- **신부대기실 복도**: 인조 잔디 바닥 + 플라워월 + 아치형 창 → 그리너리 복도 구역에 반영,
  게임 내 "초록빛 힐링 구간" 연출 포인트로 활용 가능
- **신부대기실 포토존**: 샹들리에, 플라워 소파, 아치 배경 → C1 NPC(신부) 배치 배경으로 사용

## 5. 축의대 → 연회장(뷔페) 동선 안내 (C2)

퀴즈가 아닌 **화살표 안내** 연출로 확정. 축의대에서 접수를 마치면 바닥/공중에 화살표
오브젝트가 순서대로 나타나 연회장 입구까지 경로를 안내하고, 캐릭터는 그 화살표를 따라
자동 또는 탭투무브로 이동한다 (평면도 기준: 축의대 → "입구"(연회장 좌측) → 연회장 내부).
자세한 상호작용 규칙은 [scenario.md](./scenario.md) 4장, UI 처리 방식은
[design.md](./design.md) 5장 참고.

## 6. 타일맵 제작 메모 (design.md와 연결)

- 타일 크기, 스프라이트 규격 등 구체적 기술 스펙은 [design.md](./design.md)에서 정의
- 맵 전체를 1:1로 재현하기보다, 하객이 실제로 걷게 될 동선(로비 → 신부대기실 복도 →
  포토테이블 → 축의대 → 연회장) 위주로 축약 재구성하는 것을 권장 (모바일 화면 크기 고려)
