# MINIMI_BLOCKER_FIX — 미니미 아트·합성 결함 우선 수정

## 0. 이번 지시의 우선순위

사용자는 픽셀 디자인 검수를 요청했는데, 실제 캐릭터 선택 화면에서 얼굴 파손, 눈 옆 괄호 모양 선, 머리–목–옷 연결 이상, 떠 보이는 색 조각을 발견했다. 자동 테스트 통과 및 기존 미니미의 포괄적 시각 품질 승인은 이 문제를 해결했다는 근거가 아니다.

**미니미 시각 품질 승인을 다시 열고, 이번 결함을 P1 / 출시 전 필수 수정으로 취급한다.**

- 기존 D의 새 장식/연출 작업보다 이것을 먼저 처리한다. 이미 작업한 A~D 변경은 보존한다. reset/clean/stash/revert나 무관한 재작성은 하지 않는다.
- 기존 문서의 “미니미 얼굴/헤어/옷 보존”은 캐릭터의 정체성·선택 기능·스타일을 보존한다는 뜻으로 한정한다. **잘못된 픽셀, 잘못된 기준점, 결함 있는 원본 파츠까지 보존하라는 뜻이 아니다.**
- “F24는 후보만 선별”은 전역 아트 밀도/배경 재가공에 대한 제한이다. 이 미니미 결함을 F24로 넘겨 미뤄서는 안 된다.
- 현재 진행 중인 동일 작업에서 안전한 지점에 우선순위를 전환한다. 다른 작업자가 같은 파일을 수정 중이면 먼저 충돌을 정리한다.
- 외부 배포/전송은 하지 않는다. 사용자 선택지, 기존 진행도, 방명록/사진 의미는 바꾸지 않는다.

이 패키지는 사용자가 올린 화면의 검수와 수정 요구이며, 실제 게임 소스 패치가 아니다. 아래 원인 후보를 확정 진단처럼 취급하지 말고 현재 소스와 원본 에셋으로 확인한다.

## 1. 반드시 재현할 세 화면

이미지는 `references/`에 있다. 번호는 **제출 화면에 보이는 첫 페이지의 열 순서**이지 저장된 asset ID가 아니다. 현재 registry의 실제 ID와 대조해서 기록한다. 첨부 이미지의 픽셀 폭은 브라우저 viewport나 DPR을 뜻하지 않는다.

| 참고 이미지 | 화면상 선택 | 우선 확인 |
|---|---|---|
| `01-face3-hair3-blue-shirt.png` | 남성, 얼굴 3, 헤어 3, 파란 셔츠 | 눈 바깥 흰색/회색 선 조각, 턱–목–셔츠 연결, 얼굴 중심과 몸 연결 |
| `02-face3-hair1-blue-shirt.png` | 남성, 얼굴 3, 헤어 1, 파란 셔츠 | 헤어 교체 후에도 남는 눈/목 문제, 얼굴과 목의 접합 |
| `03-face2-glasses-hair1-ivory-top.png` | 남성, 안경 얼굴 2, 헤어 1, 아이보리 상의 | 안경과 눈의 정합, 턱/목/카라 경계, 경계에서 떠 보이는 사각 색 조각 |

**세 이미지 공통:** 남성 첫 번째 얼굴 썸네일의 양쪽 눈 바깥에 긴 꺾인 선이 있어 `[ ]` 같은 형태로 보인다. 사용자가 명시적으로 수정 요청한 부분이다. 의도된 속눈썹/얼굴 디테일인지, 잔여 픽셀/덧그림인지 출처를 밝혀 수정한다. 의도된 표현이었다는 이유만으로 그대로 두지 않는다.

선택 썸네일에서 분리된 헤어, 민머리 형태 얼굴, 옷만 표시되는 것 자체는 파츠 선택 UI의 의도된 표현이다. 그것을 합성 파손으로 오인하지 않는다.

## 2. 원인 추적 — 화면 위치만 살짝 바꾸고 끝내지 말 것

현재 프로젝트에서 실제 파츠 registry, 원본/최적화 에셋, 합성 함수, atlas 생성, 표정/포즈 덧그림, 썸네일 및 런타임 렌더 경로를 찾는다. 과거 `minimi.ts`/`Player.ts` 등의 이름은 탐색 힌트일 뿐 현재 코드 구조를 가정하지 않는다.

각 결함에 대해 다음 중 **처음 잘못되는 단계**를 비교한다.

1. 원본 RGBA 파츠 및 crop/frame 경계.
2. 파츠를 같은 논리 프레임에 배치한 상태: 헤어, 얼굴, 눈/표정, 안경, 목, 몸/옷을 따로 확인.
3. 최종 합성 텍스처/atlas의 원본 해상도 1배.
4. 커스터마이저의 실제 표시 결과와 파츠 썸네일.
5. 로비, 사진 결과, 단체사진, 걷기/반응 등 실제 사용 화면.

검토 후보:
- anchor/origin/trim offset과 파츠별 crop 기준의 불일치.
- 이미 눈이 그려진 얼굴 위에 새 눈/깜빡임을 덮으면서 기존 선이 남는지.
- 안경/눈/눈썹/피부 마스크의 그리기 순서와 지우는 영역.
- 목을 누가 소유하는지(얼굴/몸/별도 레이어), 옷의 목 구멍과 겹쳐 이중 생성하거나 덮는지.
- 이전 선택의 픽셀이 canvas/texture에 남는지, 서로 다른 조합의 캐시 키가 충돌하는지.
- 원본에 이미 있는 잘못된 선/투명도와 렌더 후 생긴 문제를 구분.
- export/crop/scaling이 선 두께나 색을 손상시키는지.

**후보일 뿐이다.** 코드/이미지 근거 없이 “CSS 문제”, “안경 잔재”, “좌표 N픽셀 오류” 등으로 원인을 확정하지 않는다. 네 항목이 모두 같은 원인이라고도 가정하지 않는다.

## 3. 수정 요구

### M01 — 머리·얼굴·턱·목·카라의 접합

- 머리 전체 외곽 bounding box의 중앙을 몸 중앙에 맞추는 임시 처방을 하지 않는다. 비대칭 헤어 볼륨은 자연스럽게 비대칭일 수 있다.
- 얼굴의 방향, 턱의 목 접합점, 목의 기준점, 몸의 카라/목 구멍을 기준으로 연결을 정의한다. 정면 자세에서 의도하지 않은 기울기/어긋남/틈이 없어야 한다.
- 얼굴/옷을 바꿔도 발 앵커/몸의 위치는 유지하고, 머리와 목만 불필요하게 옆으로 튀지 않아야 한다.
- 포즈별 오프셋이 필요하면 원인이 명확한 파츠/포즈 데이터로 관리한다. 조합 이름마다 CSS translate를 추가하지 않는다.
- 원본 파츠의 설계가 맞지 않는 경우 잘못된 부분의 국소 픽셀 수정은 허용한다. 어긋난 구조를 스케일이나 배경색 덧칠로 감추지 않는다.

### M02 — 얼굴 파손 및 남성 첫 얼굴의 `[ ]` 제거

- 첫 얼굴 썸네일의 눈 양옆 긴 꺾인 선을 자연스러운 눈/눈썹/피부 표현으로 정리한다. 선택된 아바타에서도 동일하게 반영한다.
- 얼굴 3의 눈 옆 흰색/회색 막대처럼 보이는 조각을 원본 단계부터 추적한다. 눈동자·흰자·속눈썹/윤곽이 읽히는 의도된 형태로 정리한다.
- 안경 없는 얼굴에 안경 같은 선을 남기지 않는다. 안경 얼굴에는 안경을 올바르게 유지한다.
- 깜빡임/눈 뜸/표정 변화로 오래된 눈, 눈썹, 안경 테두리가 남거나 얼굴 일부가 지워지지 않아야 한다.
- 이미 파손된 결과를 새 snapshot baseline으로 등록하거나, 문제 얼굴/안경/깜빡임 선택을 없애는 방법으로 통과시키지 않는다.

### M03 — 목 경계와 카라를 의도적으로 그리기

- 머리·옷에는 진한 윤곽이 있는데 목의 양옆/턱 아래만 사라지는 불연속을 정리한다.
- 주변 아트와 맞는 윤곽/음영으로 턱 아래, 목 양옆, 카라 접합이 알아보이게 한다. 목 전체에 과한 검정 직사각형을 두르지 않는다.
- 얼굴 피부색, 목 피부색, 옷의 목 구멍이 합쳐져 빈틈/이중 목/뜬 사각형처럼 보이지 않아야 한다.
- 파란 셔츠와 아이보리 라운드 상의를 모두 고친다. 한 카라만 성공하는 패치는 허용하지 않는다.

### M04 — 떠 있는 의상 색 조각과 파츠 잔재

- 사용자가 지적한 목/의상 경계의 사각 색 조각을 해당 원본 픽셀/레이어까지 역추적해 정리한다.
- 단추·봉제선·의도된 하이라이트는 보존한다. “작은 연결 성분을 전부 삭제” 같은 자동 필터로 정상 디테일을 지우지 않는다.
- 배경과 무관하게 깨끗해야 한다. 선택 화면의 분홍색으로 잔재를 덮어 로비에서 다시 드러나는 패치는 금지한다.
- 헤어/얼굴/옷을 번갈아 선택해도 이전 파츠의 픽셀이 남지 않도록 한다.

### M05 — 썸네일·미리보기·실제 게임에 같은 수정 적용

- 썸네일만 보정하거나 큰 미리보기만 교체하는 작업으로 끝내지 않는다. 세 경로가 실제 같은 얼굴/안경/옷/파츠 정의를 사용하거나 동등하게 반영하도록 한다.
- 최종 합성 텍스처의 원본 해상도에서 깨끗한지 먼저 확인하고, 실제 화면에서 다시 확인한다.
- 캐시/최적화 파일을 사용하는 경우 오래된 에셋이 남지 않도록 변경한 원본–생성물–로더의 연결을 맞춘다. 매 프레임 텍스처를 재생성하거나 모든 조합을 boot preload에 추가하지 않는다.
- preview, 로비, 개인 사진, 신부 사진, 단체사진, 현재 구현된 걷기/박수/환호/깜빡임에서 외형과 접합을 유지한다.
- 현재 반영된 D의 저장/이어하기가 있으면 로딩 후에도 선택 ID/외형이 유지되도록 검사한다. 이 수정 때문에 별도 신규 저장 시스템을 만들지는 않는다.

## 4. 시각 검증 — 기능 테스트 수와 아트 승인을 분리

### 파츠·조합 조사

- 현재 UI에서 고를 수 있는 모든 성별/얼굴/헤어/옷 및 페이지의 실제 ID를 열거한다.
- **모든 선택 가능 조합의 정면 idle 합성**을 자동 생성한다. 개수는 실제 데이터로 계산하고 명시한다. 누락 조합은 숨기지 않는다.
- 모든 얼굴 단품, 헤어 단품, 의상 단품 및 합성 결과를 원본 픽셀 크기와 nearest-neighbor 4배로 확인한다. 4배 확대는 검수용이며 제품 렌더링 크기를 바꾸라는 뜻이 아니다.
- 수백 개를 한 장에 작게 줄이지 않는다. 원본 크기를 유지하는 여러 페이지와 ID 인덱스를 만들고, 문제가 보이면 그 자리에서 다시 고친다.
- 여자/안경 없음/안경 있음/헤어 길이/목 구멍 형태가 다른 의상도 같은 합성 경로이면 반드시 포함한다.

### 실제 표시/시간 흐름

- 사용자 세 조합은 수정 전후 동일 선택·동일 배율·동일 시점으로 비교한다.
- 320/393/430 폭과 데스크톱 실제 커스터마이저에서 확인한다. 브라우저/DPR/표시 CSS 크기를 기록한다. 사용자 캡처의 viewport/zoom은 확인되지 않았으므로 추정값을 사실로 쓰지 않는다.
- 깜빡임은 뜬 상태→닫힌 상태→다시 뜬 상태를 연속 프레임으로 확인한다.
- 현재 존재하는 방향/걷기/박수/환호 포즈는 세 재현 조합 및 각 변경 파츠·의상군을 포함한 대표 조합으로 확인한다. 정면 전체 조합 검사와 동작 대표 조합 검사를 구분해서 보고한다.
- A→B→A 얼굴/안경/헤어/옷 반복 변경, 장면 전환/재방문/사진 생성을 확인한다.
- 작게 줄여 결함을 안 보이게 하거나, 사용자만 못 보는 디버그 렌더러로 검사를 대체하지 않는다. 조합 전수 검사용 harness와 실제 플레이 렌더가 동등한지도 확인한다.

### 기능 회귀

- 관련 자동 테스트, production build, 변경 에셋의 shipping 검사를 수행한다. 실패를 예외 처리하거나 assertion을 약화하지 않는다.
- 변경한 원본 에셋의 사용 장면/캐시/로드 경로, 사진/외형 선택 ID, 발 앵커/이동을 확인한다.
- 초기 로딩을 재측정하고 새 아트 때문에 전체 조합 선로딩이 복구되지 않았는지 확인한다.
- 전체 게임을 처음부터 재작성하거나 무관한 UI를 바꾸지 않는다.

## 5. 완료 조건

아래 네 사용자 불만을 각각 근거 이미지와 함께 닫는다.

1. 머리–목–몸 연결: 같은 자세에서 기준점/접합이 자연스럽고 헤어/옷을 바꿔도 틈·불필요한 어긋남이 없다.
2. 얼굴: 첫 얼굴의 괄호형 선과 눈 주변 파손이 썸네일/preview/게임에서 제거됐다.
3. 목: 턱 아래·양옆·카라 연결에 주변 아트와 일관된 윤곽/음영이 있다.
4. 의상: 경계의 뜬 조각/이전 선택 잔재가 없고, 정상 단추·하이라이트는 보존됐다.

**자동 테스트 PASS와 시각 PASS를 별도 열로 보고한다.** 원본/합성/표시 단계를 실제로 보지 못했다면 미검증으로 쓴다. 결함이 남았는데 “기존 스타일 보존”, “F24에서 검토”, “테스트는 통과”로 완료하지 않는다.

전체 아트를 임의로 재생성하지 않는다. 국소 수정으로도 품질을 맞출 수 없으면 필요한 파츠의 정확한 파일/문제/대체 조건을 적고 해당 항목을 BLOCKED로 남긴다. 깨진 출력을 정상으로 승인하지 않는다.

## 6. 한 번의 결과 전달

내부에서 재현→원인 확인→수정→시각 재확인까지 반복한다. 사용자에게 파일별/조합별 중간 승인을 요청하지 않는다.

결과 폴더: `docs/game-review/minimi-fix/`
